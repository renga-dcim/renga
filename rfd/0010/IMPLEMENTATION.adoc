= RFD 0010 implementation checklist

Implements link:README.adoc[RFD 10: Power inventory and topology].

== Phase 1: Panels and feeds

* [ ] Add power panels at sites and locations, and power feeds with supply,
  phase, voltage, amperage, maximum utilization, side, and optional rack.
* [ ] Define voltage/current conventions and show usable AC capacity in VA and
  DC capacity in W on a site power page, never mixing W, VA, and A.

== Phase 2: Ports, outlets, and connections

* [ ] Create typed power ports and outlets from catalog templates, including on
  existing assets.
* [ ] Add the `power` cable kind to the RFD 7 plan, assertion, and cable model.
* [ ] Compute each device's power path and show where an incomplete path stops.

== Phase 3: Load and redundancy

* [ ] Add an optional organization-wide default power factor, labelling any
  headroom computed from it.
* [ ] Sum allocated watts per feed and per three-phase leg; require explicit
  power-factor provenance for AC conversion and show unknown headroom when
  conversion or leg coverage is incomplete. Test non-unity power factor and
  an overloaded leg despite aggregate headroom.
* [ ] Compute redundancy by distinct feed sides and show it on devices.
* [ ] Add the "what fails if this feed fails" view.

== Phase 4: Evidence and findings

* [ ] Accept outlet and leg readings from PDU sources and show measured load
  beside allocated load.
* [ ] Accept power supply status and draw from host agents, recording each
  reading's source.
* [ ] Read hwmon power in the agent, and snapshot the SMBIOS tables with a
  failure-tolerant privileged helper. Read the two fixed source files without
  following links, atomically publish one boot-identified generation with
  agent-readable permissions under a root-owned, non-agent-writable directory,
  and reject partial or prior-boot generations.
* [ ] Scrape configured local exporters through a fixed metric mapping, loopback
  by default. Enforce the destination on actual connections, disable redirects
  and loopback proxies, bound time and decoded data cardinality in an isolated
  worker, never send intake credentials, and treat malformed or bounded-out
  scrapes as source failures rather than zero readings.
* [ ] Keep direct IPMI device access out of the main agent. Map in-band readings
  only from a locally managed ipmi_exporter and leave `PrivateDevices=true`.
* [ ] Add the RFD 10 `power_poller` collector for PDU/UPS protocols, beginning
  with PDU SNMP as the initial measured-load producer, and add the `bmc_power`
  Redfish collector. Reuse RFD 11's collector stream identity,
  credential-locality, isolated scheduling, freshness, and replay contracts
  without claiming its switch/libvirt modules provide these protocols.
* [ ] Report each power source's status in check-ins and show it on the
  Collectors page.
* [ ] Open not-redundant, near-capacity, supply-failed, unexpected-draw, and
  incomplete-path findings in a Power Inbox domain.
* [ ] Suggest supply-to-outlet connections from correlated readings, accepted
  or dismissed by an operator and never applied automatically.

== Phase 5: Measured history

* [ ] Sample readings on their own interval and deliver them in batches through
  the on-disk queue, apart from inventory observations.
* [ ] Add the `Renga.Telemetry.Store` behaviour and the built-in adapter keeping
  five-minute averages for 30 days in Postgres.
* [ ] Show measured-load trends on feeds and devices, keeping findings and
  capacity on the latest readings only.
