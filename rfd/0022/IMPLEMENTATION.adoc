= RFD 0022 implementation checklist

Implements link:README.adoc[RFD 22: Operator API].

* [ ] Add hashed operator tokens with immutable IDs, unique names, scopes,
  expiry, and source address lists, created and revoked by `renga
  operator-tokens` release commands; support self-revocation, and keep the API
  off while no token exists.
* [ ] Authenticate operator tokens separately on every request, including
  expiry and revocation, and derive source addresses only from the peer or
  explicitly trusted proxies.
* [ ] Serve `/operator/v1` over HTTPS with an OpenAPI description, and support
  internal-only mode that removes the public route and binds to a restricted
  address.
* [ ] Add organization create, rename, suspend, resume, scheduled deletion and
  cancellation with a 30-day grace period, and read endpoints; serialize
  cancellation against purge and preserve shared users and audit attribution.
* [ ] Enforce suspension and entitlement removal on HTTP, sockets, data
  delivery, agent requests, job dispatch and renewal, and active sessions.
* [ ] Add expiring, revocable, single-use owner invitations bound to an
  organization and verified email; test atomic acceptance, deployment sign-in
  policy, and that the operator never receives a sign-in link or sets a
  password.
* [ ] Add the policy document for limits, locked settings, and entitlements,
  with environment defaults and read-only locked settings in organization
  settings.
* [ ] Manage durable runtime deployment identity providers while leaving
  environment providers read-only; bind test sign-in to a configuration
  version, encrypt secrets, and atomically prevent sign-in or sudo lockout.
* [ ] Record daily usage totals and serve current counts and totals.
* [ ] Add staged exports and imports with credential exclusion, token-bound
  short-lived downloads, atomic empty-destination enforcement, and explicit
  transfer authority tests.
* [ ] Require durable, request-bound `Idempotency-Key` handling for
  non-idempotent actions, including concurrent and asynchronous retries, and
  require atomically checked `If-Match` versions on document writes.
* [ ] Preserve, replace, and clear write-only provider secrets explicitly.
* [ ] Record sanitized immutable attribution for attempted mutations in the
  deployment audit log and successful organization changes in Activity,
  transactionally coupled to the change without credentials or capabilities.
* [ ] Add a release command for every API operation using the same domain
  mutation, precondition, idempotency, lockout, and audit contracts.
* [ ] Test the operation-to-scope matrix and that no endpoint outside an
  authorized transfer returns inventory data, a secret, or a session.
