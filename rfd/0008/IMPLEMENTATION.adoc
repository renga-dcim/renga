= RFD 0008 implementation checklist

Implements link:README.adoc[RFD 8: Product experience].

== Phase 1: Foundation

* [X] Define color, type, spacing, and radius tokens as CSS custom properties
  on plain Tailwind, including fixed status colors with an ochre warning.
* [X] Define comfortable and compact density tokens, with 44px minimum tap
  targets on touch devices, and exercise both densities in UI tests.
* [X] Remove daisyUI and migrate core components to the tokens.
* [X] Build the shared list, object page, properties panel, status strip, side
  panel, and confirmation components.
* [X] Drop the generator suffix from the page title.

== Phase 2: Navigation

* [X] Generate the sidebar, mobile menu, and command menu from one navigation
  definition with the six top-level areas.
* [X] Redirect existing routes to their new locations.
* [X] Add contextual command menu actions that explain unavailable actions.

== Phase 3: Inventory and object pages

* [X] Move Inventory onto the shared list with URL state, saved views, and
  keyboard navigation.
* [X] Move resource object pages onto the shared layout with domain tabs.
* [X] Show provenance and drift on individual values.

== Phase 4: Inbox

* [X] Add organization-scoped finding workflow state: assignee, snooze, and
  exceptions with reason and expiry, used by every finding domain.
* [X] Build the unified Inbox and retire the separate findings pages.
* [X] Add member requests with approval and similar-request suggestions.

== Phase 5: Triage

* [X] Compute triage from missing placement, hardware type, owner, and
  duplicate-identity facts, excluding virtual machines.
* [X] Group triage by pattern and suggest rules for common patterns.
* [X] Add network-location, top-of-rack switch, and ownership rule types with
  match previews, rule provenance on set values, Activity entries, and no
  overwriting of person-set facts or rack units.

== Phase 6: Places

* [X] Build the rack elevation with front and rear faces, observed-elsewhere
  devices, and drag-to-place for unplaced resources.

== Phase 7: Network

* [x] Rebuild topology with plan, evidence, and cable record shown per link.
* [x] Add the switch Ports tab with front-panel view and in-place VLAN drift.
* [x] Rebuild VLAN views with ID-range usage and planned versus observed
  membership.
* [x] Add scale-aware prefix views, IPv6 presentation, and address-family and
  routing-table switches.

== Phase 8: Component editing

* [x] Add the expected-versus-observed Hardware tab with intent-based edits and
  role-based permissions.
* [x] Add catalog draft revisions with grouped templates and impact preview.
* [x] Add per-resource and bulk revision moves with preview and optional
  automatic moves.

== Phase 9: Appearance and remaining pages

* [x] Store theme, accent, and density per user with an organization default
  accent.
* [ ] Restyle authentication and settings pages onto the shared components.
* [ ] Verify every phone-complete task at 390px width in UI tests.
