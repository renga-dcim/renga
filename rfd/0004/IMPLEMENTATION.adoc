= RFD 0004 implementation checklist

Implements link:README.adoc[RFD 4: IP address management].

== Phase 1: Harden prefixes

* [x] Require the owner/admin policy for prefix envelopes and typed prefix
  writes, re-checked in the database inside the transaction.
* [x] Add prefix create, edit, and delete in the Network area, defaulting to the
  global table.
* [x] Add the `container` status and enforce exact CIDR uniqueness per
  legacy exact-string routing table; replace this constraint in Phase 2.
* [x] Build hierarchy with strict containment so a prefix is never its own
  parent.
* [x] Count distinct observed hosts in the shipped prefix views; count queries
  do not enumerate address space, while small address maps remain bounded.

== Phase 2: VRFs

* [x] Add optional organization-scoped VRF resource envelopes and typed
  projections; null `vrf_id` remains the global routing table.
* [x] Replace `Prefix.vrf` text with a nullable tenant-safe VRF association,
  preflighting every many-to-one mapping including blank/`default` to global,
  requiring operator approval by renaming, and rejecting resulting exact-CIDR
  conflicts. Test case variants with contained but non-identical CIDRs.
* [x] Replace interim prefix uniqueness with null-safe global/VRF constraints.
* [x] Make utilization namespace-local with unions of child-prefix space.
* [x] Switch the prefix views' routing-table selector to VRF records.
* [x] Add `/network/vrfs`.

== Phase 3: Managed addresses

* [x] Evolve `managed_addresses` into `ip_address` envelopes and typed
  projections that retain the intended mask while enforcing managed identity by
  namespace and host value.
* [x] Keep lifecycle, allocation state, management mode, and shared-address role
  orthogonal in the managed address model.
* [x] Include managed-but-unobserved occupancy in distinct-host utilization,
  combining managed intent and observed hosts without double-counting.
* [x] Apply status-specific container utilization, including empty containers,
  separately from the existing child-driven presentation mode.
* [x] Add optional assignments with tenant-safe constraints, address-row locking,
  ordinary single-assignment validation, and explicit shared-address roles.
* [x] Move Adopt and release onto the new model in one transaction each, writing
  change events, and migrate existing managed addresses with their interfaces.
* [x] Test adopt, release, and re-adopt of the same canonical identity, including
  surviving observed-only occupancy, ended assignments, retired-role behavior,
  and separate removal of one shared assignment.
* [x] Add `/network/addresses` with managed-address search, reservations, and
  assignments.

== Phase 4: Observed identity

* [x] Change observed-address identity to interface plus host value while
  preserving every reported address and mask in observation evidence, merging
  existing same-host rows.
* [x] Update evidence uniqueness and ingestion idempotency before reparenting;
  test same-observation `/24` and `/32` reports, replay, and presence history.

== Phase 5: Address findings

* [ ] Add the `address` finding domain to the Inbox with the shared workflow:
  assignment, snoozing, accepted exceptions, and member requests.
* [ ] Add the strict unmanaged-address policy to prefixes, off by default.
* [ ] Surface unmanaged-in-strict-prefix, outside-prefix, stale managed,
  duplicate, and prefix-length findings with source evidence, and show them on
  the affected prefix, address, and resource pages.
* [ ] Resolve findings as observed state converges without deleting immutable
  observation or change history.

== Phase 6: Routing domains

* [ ] Add observation-linked routing-domain claims, authoritative source
  capability, external-domain mapping, stale membership handling, and an
  unmapped-domain outcome; absent claims remain global.
* [ ] Define finding precedence and correlate active observed assignments by
  resolved namespace and host value without treating same-address use in another
  VRF as inherently wrong.
* [ ] Surface wrong-VRF and unmapped routing-domain findings.

== Phase 7: Addressing plan and allocation

* [ ] Add an optional per-family organization addressing plan that drives the
  child-space map's planning levels.
* [ ] Add a serialized next-free prefix and host allocator for owners and
  admins, sharing organization-first locking with all managed writes affecting
  availability and excluding known occupied and non-assignable space.
* [ ] Prove allocation safety under allocator-versus-allocator,
  allocator-versus-manual-write, and prefix-resize races, with availability
  checks and durable allocation in the same transaction.

== Throughout

* [ ] Add context, constraint, query, reconciliation, authorization, concurrency,
  migration, and LiveView tests for global, VRF-scoped, IPv4, IPv6, shared, and
  conflicting behavior.
* [ ] Run `make check-rfds`, focused IPAM tests, and `mix precommit` before marking
  the proposal implemented.
