= RFD 0023 implementation checklist

Implements link:README.adoc[RFD 23: Deployment identifiers and agent home resolution].

* [ ] Add the optional deployment identifier to deployment configuration,
  validate its form, and include it in newly issued intake keys between the
  prefix and the secret; test that keys with, without, and with a wrong
  identifier authenticate by hash alone.
* [ ] Show the identifier on the intake key page and report it through the
  operator API and release commands (RFD 22).
* [ ] Add `GET /api/v1/agent/home`, unauthenticated and rate limited, that
  answers with the deployment's configured public URL.
* [ ] Mark the source organization moved when an RFD 20 import completes, and
  answer its intake requests with `410 Gone` and `moved`; test that a
  suspended organization still answers `403`.
* [ ] In the agent, resolve and persist the home on first start, send
  authenticated requests only to the home, re-resolve on `410 moved` with
  backoff when the home is unchanged, keep redirects disabled, and enforce
  `https` on the resolved home; test resolution against a deployment, against
  a stub resolver, and across a simulated move.
* [ ] Log `renga_url`, the resolved home, and the resolution time at agent
  startup and after each resolution.
