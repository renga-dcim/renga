= RFD 0017 implementation checklist

Implements link:README.adoc[RFD 17: Attribute-based authorization].

* [ ] Add `Renga.Authorization` with the permission catalogue and built-in
  roles, and a parity test covering every public mutation for each built-in
  role and for machine scopes; it must pass before and after the next item.
* [ ] Replace every hard-coded role list and `organization_manager?`-style
  hint with permission checks, and turn unchecked public mutations into
  explicit system paths. Preserve supported human workflows and machine
  behavior; deliberately close undocumented low-level human entry points that
  previously skipped authorization.
* [ ] Add member management in organization settings: invite, disable, change
  base role, with Activity entries and at least one active, direct,
  non-expiring manual recovery owner.
* [ ] Add team membership, managed with `teams.manage`, and treat membership
  that confers access as a grant transition.
* [ ] Add code-defined owner and admin grant ceilings, custom roles and
  unconditioned assignments. Keep `members.manage` and `roles.manage` out of
  custom roles. Test that admins can assign `member` and bootstrap authorized
  explicit permissions without acquiring their actions, but cannot grant
  `owner`, `organization.manage`, or `organization.export`. From a state where
  nobody holds an explicit permission, test issuance of every explicit role and
  its recipient and lifetime rules.
* [ ] Add conditions on `resource`, `kind`, `owner_team` (including
  `$subject_teams`), and `site`, compiled to SQL predicates, with `filter/3`
  for lists and whole-batch refusal for bulk actions. Reject unknown vocabulary
  and cross-organization IDs. Derive complete target sets on the server and
  require unconditioned authority when that is impossible before a change.
  Require unconditioned grant authority for recipient-relative or dynamically
  expanding conditions.
* [ ] Add the per-resource access row, updated in the same transaction as
  placement and ownership changes and authorized against both states.
* [ ] Filter every read path by `inventory.read`: lists, fetches (hidden reads
  as not found), search, counts and badges, exports, Activity, shared views,
  and aggregates that show hidden resources only as occupied. Declare each
  public read function's permission and test that none is undeclared, with a
  scoped-member suite over all of them.
* [ ] Implement the disclosure matrix for raw observations, mixed-resource and
  historical records, query and VM payloads, terminal recordings, and
  organization-wide records. Use typed safe projections or withhold opaque
  payloads; test hidden neighbor identifiers, snapshots, generic Activity and
  job views, mutation responses, and exports. Test that an ID-scoped reader does
  not learn an unconfirmed placement's hidden container ID or metadata; once
  placement is confirmed, expose only its breadcrumb projection unless the
  reader independently holds `inventory.read` over the container.
* [ ] Require `inventory.read` over every target of a human mutation in addition
  to its action permissions, and return only those readable targets.
* [ ] Make live updates carry IDs only and re-fetch through each subscriber's
  scope; test that losing read access removes a resource from an open page.
* [ ] Allow memberships with no base role.
* [ ] Enforce the before-and-after rule for owner team and placement changes,
  for direct edits and request approval. Apply the grant ceiling to effective
  access added by team, role, external-source, ownership, and placement changes.
* [ ] Restrict confidentiality and operational permissions to trusted
  attributes. Test that owner teams set by triage rules and unconfirmed
  placement neither reveal existing hidden data nor authorize `jobs.request`.
* [ ] Add one locked organization authorization version shared by policy
  changes, resource-access changes, and protected mutations. Refresh connected
  LiveView scopes on role, membership, assignment, team, source, and expiry
  changes, and check versions and deadlines before protected data delivery and
  events. Test that each revocation path stops both reads and mutations.
* [ ] Add explicit permissions with the operation-specific action, retained
  payload, approval, audit, and lifetime rules in RFD 17, ready for RFDs 12, 13,
  and 14. Test that terminal replay remains owner/admin-only and audited rather
  than becoming delegable through a custom role.
* [ ] Add the access views on member and resource pages, and name the missing
  permission when an action is refused.
* [ ] Amend RFDs 12, 13, 14, and 15 to use assignments and the disclosure table.
