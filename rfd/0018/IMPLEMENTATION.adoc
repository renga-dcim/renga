= RFD 0018 implementation checklist

Implements link:README.adoc[RFD 18: Resource groups].

* [ ] Add resource groups and group sets, managed with `groups.manage`.
  Materialize deduplicated effective memberships and enforce exclusive sets in
  the database for both authorization views. Reject rather than choose between
  direct/inherited or ancestor/descendant conflicts; test membership,
  placement, hierarchy, group-to-set, exclusivity-enabling, and concurrent
  writes.
* [ ] Add membership changes from resource pages, group pages, and bulk
  selections, requiring `inventory.edit` and RFD 17's before-and-after rule over
  every directly or transitively affected resource; refuse the whole operation
  when any descendant is unauthorized, and test that no agent, reconciler, or
  triage rule path can change direct membership.
* [ ] Extend membership from sites, locations, and racks to placed resources,
  deriving separate current-placement and fully confirmed-path views. A
  reconciler may update only the current view. Serialize every membership,
  group-set, placement, hierarchy, and reconciliation write on the shared
  organization-and-group-projection lock before existing hierarchy or rack
  locks; test concurrent membership and placement changes and whole-change
  rollback.
* [ ] Add separate current and trusted effective group IDs to the RFD 17 access
  row and select them by permission class for the `group` condition. Test that
  observed placement cannot grant operational access, and that removing one
  inheritance path preserves an independent direct or inherited path.
* [ ] Remove deleted groups from conditions so emptied clauses match nothing,
  and flag those assignments in the access view.
* [ ] Limit group visibility to managers, assignment holders, and people who
  can read a member; test that group names and counts never reveal hidden
  resources.
* [ ] Record group, set, and membership changes in Activity.
